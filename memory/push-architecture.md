Push = **free external sender**, staying on Firebase Spark (no Blaze). Pieces:
- Apps register each device's **FCM token** (via `expo-notifications` `getDevicePushTokenAsync`) into
  Firestore `pushTokens/{uid}` ({ token, kind:'admin'|'buyer' }).
- A **Cloudflare Worker** at `functions/notify/` holds the Firebase **service account**
  (`FIREBASE_SERVICE_ACCOUNT` secret), reads recipients from Firestore, and sends via **FCM HTTP v1**.
- Apps POST events to it (`notifyUrl` in each `app.json > expo.extra`): `new-order` → admins ring,
  `order-status` → that customer, `back-in-stock` → customers whose `notifyBackInStock` has the productId.
- The 10-second ring = admin Android channel `orders` (importance MAX) + bundled
  `admin-app/assets/sounds/order-ring.wav` (generated by `scripts/gen-sound.mjs`).
- `sendNotify`/`getIdToken` live in `common`; push is a graceful no-op when `notifyUrl` is empty.

**Accepted caveat:** the Worker does a CLAIM-CHECK on the caller's Firebase ID token (aud/iss/exp),
NOT full RS256 signature verification (Web Crypto can't import Firebase's X.509 certs without a dep).
So a forged token with the right claims could trigger spam notifications — low impact (notifications
only). Hardening path (JWK endpoint + `crypto.subtle.verify`) is documented in `functions/notify/README.md`.
